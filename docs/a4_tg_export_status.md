# A4-③ 状态：`.TG` 闭环 —— 可行但**不稳定**，尚不能算达成

记录时间：2026-10-29。全部为本机实测（引擎 `BUILD 2026-10-18-v3.8-gguf-native-experimental`）。

## 1. 已经确定的（可复现）

| 项 | 结果 | 复现方式 |
|---|---|---|
| `.TG` 写入器存在且可用 | ✅ | `tgai_go/pack.py` 的 `TGWriter`；`build_dummy_tg` 写的文件引擎能跑 |
| 我们的导出器**字节确定** | ✅ | `tg_export_roundtrip.py --selftest`：两次导出 sha256 相同（55,140 字节） |
| 引擎能**加载**我们导出的文件 | ✅ **5/5** | `tgai_go.load(path)` → `Model` |
| `generate()` 能产出文本 | ⚠️ **时好时坏** | 见下表 |
| 权重命名 | ✅ 已修正 | 引擎要 `blocks.{i}.**moe.**experts.{e}.w1.weight`（比训练侧多一层 `moe.`）；漏了会 `access violation` |

## 2. 不稳定的证据矩阵（同一份代码、同一台机器）

| 条件 | 成功次数 | 现象 |
|---|---|---|
| 随机权重（scale=1.0），`tg_export_roundtrip.py --check` | **3/5** | 失败：`access violation reading 0xFFFFFFFFFFFFFFFF` |
| 随机权重 + 贪心（`temperature=0, top_k=1`） | **3/5** | 同上 ⇒ **不是采样导致** |
| 随机权重（scale=1.0），改用 `subprocess -c` 起进程 | **0/5** | 进程直接被杀（段错误，无 Python 异常） |
| 随机权重（scale=0.2），同上 | **0/5** | 同上 |
| **全零权重**（norm=1 其余=0） | **段错误** | 进程被杀，连异常都来不及抛 |

**结论**：崩溃是**引擎侧的**（读 -1 当地址 / 段错误），且与权重退化程度相关；
`subprocess -c` 与直接调用的成功率差异说明它对运行上下文也敏感。
**这不是导出器的问题**（导出、加载、命名都已验证正确），而是**引擎对退化/合成权重没有防护**。

## 3. 为什么本轮不判定 A4-③ 完成

A4-③ 的原文要求是"**训练完**直出 `.TG` 被自家引擎加载"。
现在验证到的是"**随机/零权重**导出的文件能被加载、有时能生成"，两者不是一回事：
- 真实训练过的权重不会退化到全零；
- 但我**还没有一个与引擎同名同构的 TGAI 架构训练产物**（现有训练侧预设是 llama/GPT-2/Qwen2/V3，
  与引擎的 TGAI 原生架构（九标记词表 + `moe.router/gate` + RMSNorm/RoPE）不同名）。

## 4. 要达成还差什么（二选一，或都做）

1. **在训练侧实现"引擎同名"的 TGAI 原生预设**（B4 的 V3 或 V2.7 形状），训几个 step，
   用它导出——这才是 A4-③ 想验的真实路径；
2. 或者**在引擎侧加越界防护**（`generate` 里对 token id / 权重指针做范围检查），
   让退化权重也能安全返回错误而不是崩进程。

第 2 条其实更重要：**引擎会因为一份"合法但退化"的模型文件而段错误，这在生产上不可接受** ——
用户随便给个坏模型就可能把服务打挂。建议单独立项。
