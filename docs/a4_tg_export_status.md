# A4-③ 状态（**已更正**）：`.TG` 闭环机制成立，但引擎有内存安全缺陷

记录时间：2026-10-29（本版修正了同日早些时候的一版**错误证据矩阵**）。
引擎：`BUILD 2026-10-18-v3.8-gguf-native-experimental`。

## 0. 更正说明（重要）

早些时候我在本文件写过一张矩阵，声称"子进程 0/5、全零权重段错误 ⇒ 引擎在 generate 时崩"。
**那张矩阵是错的**，原因是我用**退出码 `== 0`** 判定成功：

- 引擎在**进程退出阶段**损坏堆，退出码是 `0xC0000374`（3221226356）或 `0xC0000005`（3221225477）；
- 因此**即使生成完全成功**，退出码也不是 0，被我错误计为失败。

→ 教训：**判据要盯"输出是否产生"，不要盯"退出码是否为 0"**，除非先确认退出路径干净。

## 1. 更正后的实测（只认 stdout 里有没有 `GEN`）

| 文件 | 生成成功 | 退出码 |
|---|---|---|
| **已知能跑的合成文件**（`build_dummy_tg`，vocab=4） | **5/5** | 全部 `0xC0000374`（堆损坏） |
| 我们的导出（随机权重，vocab=64） | **5/10** | `0xC0000005`×6、`0xC0000374`×4 |
| 我们的导出（全零权重） | **5/5** | — |
| 我们的导出 `special_ids=[0,0,0,0]` / `[0,1,2,3]` | 6/8 / 7/8 | — |

**结论**：
1. **机制成立**：导出 → `load`（100% 成功）→ `generate` 能产出文本；
2. **引擎有两个独立的内存安全缺陷**：
   - **堆损坏（退出阶段）**：所有文件都中，包括仓库自带的"能跑"样例 → 说明不是我们的文件导致；
   - **访问违例（运行阶段）**：我们的文件约 20–40% 触发，仓库样例不触发 → **与文件内容相关**，
     具体触发点未定位（已排除 `special_ids`、采样方式、权重是否退化）；
3. 因此 **A4-③ 的机制已被证明可行，但不能判定"稳定达成"**。

## 3. 建议（按优先级）

1. **引擎加内存安全防护**（高优先级，生产风险）：`generate` 里对 token id、权重指针做范围检查；
   并修退出阶段的堆损坏 —— **任何一份合法但内容异常的 `.TG` 都可能把服务打挂**。
2. 定位"访问违例"的触发点：用二分法改文件内容（词表大小 / 权重形状 / 层数）逐项排查；
3. A4-③ 的正式判据：用**训练过的、与引擎同名同构的 TGAI 模型**导出，要求 `generate`
   **连续 8 次全部产出文本**（且理想情况下退出码为 0）。
